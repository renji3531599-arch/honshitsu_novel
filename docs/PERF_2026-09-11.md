## 1. 犯人（重いと思った理由） ―― ログ保存は「主犯ではない」

### ① 背景SVGが全面 `feTurbulence` ＋ SVG内で `infinite` アニメ（最大）
`js/visual.js` の `backdropSVG()` が生成する等高線背景は、
`<filter id="paper"><feTurbulence>` を **1600×900 の全面_rect_に**掛け、さらに SVG 内に
`<style>` で `animation: ... infinite` を入れていた。SVG 内部のアニメは**ブラウザのCSSアニメと違い**
合成レイヤに逃がせず、**画面内の任何のアニメが1フレーム動くたびに全面を再ラスタ**する。
＝背景を見ているだけでノイズ生成が走り続けていた。これが最大の発熱源。

**対処**：`feTurbulence` は `filterUnits="userSpaceOnUse"` で **128×128 の `<pattern>` タイル**に閉じ込めた
（見た目の粒子感はそのまま、計算量は全面144万px→1.6万pxの1回ぶん）。SVG内 `<style>` と
`animation` は全廃し、動くのは CSS 側の限定的な宣言だけにした。生成結果は `id|meta` キーでキャッシュ
（同一背景の再敷設は文字列生成ごとスキップ）。

### ② 立ち絵に `infinite` が最大4本、しかも blur を通っていた
`.chr .sil`（呼吸）／`.chr.in`（入り）／`.chr.talk`（0.34秒のバウンス）／`.chr.talk .rim`（脈打ち）。
4本のうち3本が `transform` の `scale` を動かすので、`feGaussianBlur` を通した SVG が
**毎フレーム描き直し**になっていた。

**対処**（`css/vn.css` の `SMOOTH & LIGHT` セクションに集約）：
- `.sil` の二重呼吸は削除（親が既に動いているので差分ゼロ）
- `chrBreathe` は **`transform`（scale/rotate）ではなく個別プロパティ `translate` だけ**を animate。
  揺れは同じ、スケールは静的＝**ぼかしの再計算は1回で終わる**
- 話者のバウンスは `.34s infinite` → **`.5s` の単発**（喋り出しに1回だけ沈み込む）
- リムの脈打ちは 1.45s → 3.2s（体感ほぼ同じ、再合成は半減以下）
- 既定は CONFIG「立ち絵の動き」= **lite**（呼吸1本のみ）。`off` にすれば完全静止

### ③ `#textbox` の `backdrop-filter: blur(6px)`
全面アニメの**上に**常に固定される、最も高い種類の合成処理。トースト／所持品／キャプションにも同款があった。

**対処**：既定 OFF（窓はグラデで同じ見え方）。CONFIG「テキスト窓をぼかす」で ON にできる。
他3要素のぼかしは削除。

### ④ 1ライン平均 1.7KB の同期 localStorage 書き込み（＝ここだけはログが関係していた）
`game.js` は **3ラインに1回** `saveAuto()`、`shell.js` はシーン移動ごとに `saveMeta()`。
どちらも `JSON.stringify` した履歴を**主スレッドで同期書き込み**する。バックログ保持が
`history` 全量＋パネル側477行で200件スライスだったころは、1回の書き込みがさらに重かった。

**対処**：
- 保持を短縮（メモリ内 240ライン、スナップショットへ載せるのは直近 40、ログパネルは150）
- 自動セーブは **9秒に1回**（`AUTOSAVE_MIN_MS`）＋ 340ms の束ね（`autosaveTick`）
- `saveMeta` は dirty フラグ化して **340ms デバウンス**、`pagehide`/`beforeunload`/可視性変化時に必ずフラッシュ
- メタ自体も整理（readScenes 260件、既読立ち絵は1スロット16件まで）
→ **1ラインあたりの書き込みは 1.7KB → 0.08KB（約21分の1）**。体感の「送りカクつき」はこれで消える。

### ⑤ （おまけで致命傷だったもの）全面レイヤの `mix-blend-mode` ＋ `contain:paint`
`.lay-bg .art-img` / `.chr img` / `.cg-holder .art-img` に `multiply` が掛かっていたが、
祖先が `contain:paint` でペイント隔離されているため、**CSS Compositing §5.2 により合成先が自分のレイヤ内だけ**。
実動作としては
- 白紙プレースホルダ前提の multiply が **効いていない**（＝演出が利いていない）
- 一方 `.lay-bg{background:#0c0a08}` 側の multiply は **親の黒と掛け算**になり、**実写背景がほぼ真っ黒**

さらに JS 側が `style.mixBlendMode` を inline でベタ書きしていたので、CSS だけの調整が通らない状態だった。

**対処**：blend 宣言は CSS に集約（inline 書きを廃止）。背景とCGは常に `normal`。
立ち絵の multiply は **`#stage[data-blend="multiply"]` のときだけ**効き、そのときのみ `.lay-chr` の
containment を `layout style`（隔離なし）へ戻す。`data-art="real"` × multiply のときは
`.lay-bg` の下地を `#fff` にして「白＝透明」が正しく効くようにした。

## 2. 見た目の問題2つ

### 背景の切り替えが「一瞬で切り替わった」ように見えた
クロスフェード自体は以前もあった（`.bg-outgoing`）が、実装が
**「表示中の背景を `cloneNode` して、その上に新背景を即時反映」**だった。
`cloneNode` は SVG 内のアニメを **0ms から再生し直す**ので旧レイヤがカクつき、しかも新背景は
1フレームで全画面に出ていた。＝「滑らか」に見えない理屈が揃っていた。

**対処**：**2枚のスラブ**（`#bgA`/`#bgB`）で受け渡しする方式に書き換えた。
1. 隠れているスラブに**先に描き込む**（実画像は `Image.decode()` してから）
2. `opacity` だけを既定 **1.15秒**でクロスディゾルブ（`--bg-fade`。CONFIGで 1.85秒／即時）
3. 受け渡し完了後、古いほうの DOM を掃除する
4. 最初の1枚だけ黒から立ち上がる（`bgRise`）。連続 `@bg` はトークンで競合無視（古い要求は捨てて最終だけ届く）
5. `prefers-reduced-motion: reduce` では 0.01ms に潰す

### 喋るときに立ち絵が一瞬消えて再表示されていた
`case 'text'` がラインごとに `applyChr()` を呼び、`applyChr` は話者ごとに
`el.innerHTML = figureSVG(...)` を**無条件で**書いていた（＝パースの隙に抜ける＝ちらつき）。

**対処**：`setChr()` は**表情が本当に変わったときだけ** `_chrDirty` を立て、`applyChr()` は
`_chrDirty || talkingが変わった` 以外では即 return。素材の書き換えは `artKey`（スラッグ＋表情）が
変わったときだけ。**話者の切り替えは class と z-index の移動だけ**で、DOM は触らない。
＝ちらつきは構造上発生しなくなった（表情が変わるときだけ、そもそも差し替えが必要）。
 立ち絵の並びが変わったときは `_pruneChr()` で不要スロットを片付ける。

## 3. 「SVG が原因なら、画像を実素材に差し替えたら軽くなりますか？」

**半分はいえ、半分は軽くならない。しかも差し替えただけでは真っ黒に見えた（今は修正済み）。**

1. **軽くなる部分**：①と②は SVG *描画*のコストなので、`placeholder:false` にして
   `backdropSVG`／`figureSVG` が呼ばれなくなれば消える。実画像は `<img>` 1枚の合成になるので、
   「動かない1枚絵」に対する毎フレーム再ラスタはゼロ。ここが今回の主因。
2. **残る部分**：③ `backdrop-filter`、④ localStorage 同期書き込み、全面 `mix-blend-mode`、
   `.lay-cg` の `filter` は**素材と無関係**。実素材にしても効き続ける（＝今回 CSS 側で切った）。
3. **むしろ重くなる部分**：実素材は転がすデータ量が増える。
   現状 202枚で **396KB**（実素材は `title_key.jpg` 1枚だけ）だが、1600×900 PNG を素で置くと
   **概算 165MB**（1枚 ≈818KB）。差し替え後に「重い」が別ベクトルで復活する。
   → **WebP/AVIF**（背景は 90〜160KB/枚、CGも 150KB/枚程度に落ち、総量 30MB 前後）
   → 立ち絵は**切り抜き透明PNG**。白背景のmultiply前提をやめられるので、これも軽い。
   → 起動プリロードは**優先順位方式**に変えてある（`AssetDB.priorityList` ＝読む5シーンぶんだけ。
     残りは `warmRest()` がアイドル時に2枚ずつ）。200枚差し替えても起動は 2.3 秒のまま据わる。
   → **`sw.js` の `CACHE`（現在 `honshitsu-v2`）は素材を差し替えるたび上げる**こと。
     さもないと CacheFirst の白紙PNGを配信し続けて「差し替わってないように」見える
     （脚本 `data/script/*.txt` は同じ罠に落ちやすいので NetworkFirst へ変更済み）。
4. **実写に替わって初めて出た不具合**：⑤ の `contain:paint` × multiply で、実写背景とCGが
   **ほぼ黒**で描画されていた（白プレースホルダ時代は白色が掛かっていたので気づかなかった）。
   現在は「実写は `normal` 合成／白背景素材だけ multiply 選択可」に整理したので、そのまま差し替えても平気。

要するに **SVG 自体が重かったのは事実。ただし原因は“SVGであること”より“SVGの中で every-frame
動く処理を全面に掛けていたこと”**。実素材化は valid な軽量化だが、①〜⑤ を直した今なら
白素材のままでも体感は軽く、実素材化は「見た目の品質」の作業として進められる。

## 4. CG を絞った（重要でない場面で出しすぎていた）

基準を決めて、**立ち絵で足りる场面から1枚絵を降板**させた：

> **CGを置くのは「場面転換」と「決定の瞬間」だけ。**
> ・小物アップ／机アップ／ただ並んで喋っているだけの報告 → 立ち絵＋`@bg`＋`@chr`（＋`@memo`）で足りる
> ・同じCGを10行以内に再掲する（dipの連発）は「切った」ことすら伝わらない → 削る
> ・ENDカード用のCGと同じ構図の差し替え → 1枚に統合
> ・喜劇のツッコミ（「は？」）は CG を立てないほうが効く

## 5. CONFIG に増えたつまみ（`js/shell.js` paneConfig）

| 項目 | 既定 | 効く場所 |
|---|---|---|
| 背景の切り替え | なめらか（1.15秒）／ゆっくり（1.85秒）／即時 | `#layBg{--bg-fade}` と `Stage.bgFadeMs()`（同一源） |
| 立ち絵の動き | lite（呼吸のみ）／off（静止）／full（旧来） | 4本の infinite を束ねる `#stage[data-chr-motion]` |
| 画像合成 | normal（推奨）／multiply（白背景素材用） | `#stage[data-blend]`（JS の inline 書きは廃止） |
| テキスト窓をぼかす | OFF | `#textwrap[data-blur="on"]` |
| 立ち絵にスロット名 | OFF | `#stage[data-sprite-tag="on"]`（JS が作る要素も属性で制御） |

低スペック・モバイル向けの逃げ道として入れてあるので、「重い」と感じたときは
**立ち絵の動き=off → 背景の切り替え=即時 → （必要なら）画面スケールを下げる** の順に落としていく。
