## 2. 画面の幾何（すべての数値の土台）

```
#viewport  aspect-ratio: 16/9          css/vn.css:58-61
--u = 画面幅 / 1000（横画面）           js/visual.js:630-636
→ 舞台は常に 1000u × 562.5u
```

| 窓の実寸 | 1u | 立ち絵枠（420×640u） | テキスト窓の高さ（197u） |
|---|---|---|---|
| 1280×720 | 1.28px | 538×819px | 252px |
| **1600×900** | 1.6px | **672×1024px** | 315px |
| 1920×1080 | 1.92px | 806×1229px | 378px |
| 2560×1440 | 2.56px | 1075×1638px | 504px |

縦画面（スマホ）は `--u = 幅 / 620` に切り替わり舞台が縦長になるので、**立ち絵の上は切れません**（§4参照）。

## 3. セーフエリア

```
┌──────────────────────────── 1000u ────────────────────────────┐  ─┬─
│  ▲ ここは画面外（立ち絵枠の上 77.5u = 12.1%）                   │   │ はみ出し
├───────────────────────────────────────────────────────────────┤  ─┤
│                                                               │   │
│        ┌──── 420u ────┐        ┌──── 420u ────┐               │   │ 立ち絵
│        │   立ち絵 左   │        │   立ち絵 右   │               │   │ （枠は
│        │  18%  50%  82% に中心（3人時）        │               │   │  640u）
│        └──────────────┘        └──────────────┘               │   │
│ ╔═══════════════════ 900u（中央）════════════════════╗        │  ─┤
│ ║  テキスト窓 + ツールバー＝下 197u（35%）を覆う        ║        │   │ 隠れる
│ ╚════════════════════════════════════════════════════╝        │  ─┴─
└───────────────────────────────────────────────────────────────┘
```

- **下 197u（画面高の 35%）** はテキスト窓＋ツールバーが覆います
  （`#textwrap{bottom:26u}` + `#textbox` 142u + ツールバー ≒ 197u／`css/vn.css:341-343,364-368,373`）。
  半透明＋`backdrop-filter: blur` なので完全には消えませんが、**顔や重要な小物を置かない**。
  テキストが長い行では最大 250u（44%）まで伸びます（`#text{max-height:150u}`）。
- 立ち絵の配置は 1人=50%／2人=33.3%・66.7%／3人=18%・50%・82%（`js/visual.js:848-850`）。
  枠は常に 420u 幅なので、**3人時は中心間 320u＝左右 50u ずつ重なります**。

## 4. 立ち絵 CHR の構図ルール

表示枠 `.chr{width:420u; height:640u; bottom:0}`（`css/vn.css:108`）に対し、
舞台の高さは 562.5u しかありません。**枠の上 77.5u（12.1%）は `#viewport{overflow:hidden}` の外**です。

### 4-1. 21:32（840×1280）で作る場合 ― 上が切れる前提の構図

| 領域 | 840×1280 での y | 扱い |
|---|---|---|
| 上 155px（12.1%） | y = 0〜154 | **画面外。余白にする**（頭頂は y≧163px に） |
| 見える帯 | **y = 155〜885** | ここに顔・胸上・手元の重要な要素を |
| 下 395px | y = 886〜1280 | テキスト窓が覆う（腰から下。半透明なのでシルエットは見えます） |

`object-fit: contain` + `object-position: bottom center` なので、比が 21:32 なら枠を完全に埋めます。

### 4-2. 3:4（840×1120）で作る場合 ― 一切切れない

`contain` で 420×560u に収まり、562.5u の舞台内に**全身が完全に見えます**。
切れない上限は **840×1125**（w/h ≒ 0.747）。それより縦長にすると 4-1 の「上が切れる」側に戻ります。

> 現行のシルエット補完（`figureSVG`、`viewBox="0 0 420 700"` に身長 566〜640u の体）も
> 同じ枠に入っているので、一番高い塀勝也は頭頂が 23u ほど画面外です。
> **実素材で頭を切られたくないなら 3:4 で納品**が安全側。エンジンを触って解決したい場合は §8。

### 4-3. 横の余白

3人時の重なり（左右 50u＝枠幅の 12%）を踏まえ、**左右に 10〜15% の透明余白**を推奨。
腕や小物が枠いっぱいに広がると隣の人とぶつかります。

### 4-4. 解像度

1600×900 の窓で実寸 672×1024px、Retina（DPR2）なら 1344×2048px が理論上限。
**840×1280 はほぼ等倍**なので、余裕があれば 1260×1920（1.5倍）まで意味があります。
ただし 78 枚あるので容量と相談（§6）。

## 5. CG / BG の構図ルール

- **16:9 以外は端が切れます**（`object-fit: cover`）。16:9 で納品してください。
- **Ken Burns に注意**（CGのみ）: `@cg <id> kb` を付けた箇所は 26 秒で
  `scale(1.02) → scale(1.11) translate(-1.2%,-1%)`（`css/vn.css:132-135`）。
  本編の `@cg` 58 箇所うち **25 箇所が kb 指定**。
  → 1600×900 ちょうどだと終端で 1.11 倍に拡大されて甘くなります。**1920×1080 推奨**。
  → **四周 5〜6% は捨てて**、重要物は中央に。
- **背景は `bgSettle`（1.016 → 1.0）** が掛かります（`css/vn.css:89-92`、実画像のときだけ）。
  1600×900 でも僅かに拡大されるので 1920×1080 が無難。
- **CG 中は立ち絵が強制非表示**（`#stage[stage-mode="cg"] .chr{opacity:0!important}`／`css/vn.css:124`）。
  → CG はキャラを一枚絵の中に描き込む前提で。
- 下 35% はテキスト窓に覆われるのは CG / BG も同じ（§3）。

## 6. 形式と容量

| 素材 | 推奨形式 | 1枚の目安 | 全部実画像にしたときの総量 |
|---|---|---|---|
| BG 25枚 | WebP（quality 82）/ JPEG | 150〜350KB | 4〜9MB（**現状 PNG で 53MB**） |
| CG 26枚 | WebP（quality 85）/ JPEG | 200〜400KB | 5〜10MB（PNG だと 52〜78MB） |
| CHR 78枚 | **透過WebP** / 透過PNG | 200〜400KB | 16〜31MB（透過PNG だと 78〜156MB） |

- 収録済みの背景 24 枚は **1672×940〜941 の PNG で 1.7〜3.1MB/枚（計 53MB）**。WebP 化で 1/4〜1/6 になります。
- 起動プリロードは「これから読む 5 シーンぶん」だけ先に待つ優先方式（`AssetDB.priorityList`）なので、枚数が増えても起動時間は一定です。
- **拡張子を変えるときは台帳の `file` も直す**必要があります（`js/` に拡張子のハードコードはありません）。
  `node tools/sync_placeholder.mjs --adopt-ext` で実ファイルの拡張子を台帳に自動反映できます。
- 透過が必要なのは立ち絵だけ。BG / CG にアルファを付けても `cover` で全画面なので無意味（容量増）です。
- 白背景の立ち絵をそのまま使いたい場合のみ、アプリ内 CONFIG「画像合成」= multiply
  （`#stage[data-blend="multiply"] .chr img` にだけ掛かる／既定は `normal`）。**本来は透過が正解**。

## 7. 命名規則と差し替え手順

### 7-1. 命名（2026-09-13 に統一済み）

| | 版A（`index.html`・現行） | 版B（`game/index.html`・旧ビルド） |
|---|---|---|
| 置き場 | `assets/bg/` `assets/cg/` `assets/chr/` | `game/assets/img/`（1フォルダ） |
| ファイル名 | **台帳ID + 拡張子** | **同じ**（`game/js/assets_manifest.js` も新名に更新済み） |
| 実画像になる条件 | `data/assets.json` の `placeholder: false` | ファイルを置くだけ（フラグ機構なし） |
| 解決コード | `js/visual.js` `AssetDB.chrFor()`（`^chr_(.+?)_(\d+)_`） | `game/js/engine.js` `chrFile()` |
| 旧名（`chr_katsuya_01_tsujou.png` 等の短縮ローマ字） | **廃止** ― どのコードも参照していません | 同左 |

旧名は `docs/CHR_REPLACE_LIST.md` の旧版に「旧エンジン用」として並んでいましたが、
版B のマニフェスト自体が新名に更新されているため **2026-09-13 に列ごと削除**しました（履歴は `ASSET_MAP.md:226`）。

### 7-2. 手順（4ステップ）

```bash
# 1. 台帳ID + 拡張子の名前で実ファイルを置く
cp ~/Downloads/chr_mie_04_kimazui_chinmoku.png  assets/chr/

# 2+3. 台帳の placeholder を false にして sw.js の CACHE を上げる（自動）
node tools/sync_placeholder.mjs --bump

# 4. 検証
node tools/sync_placeholder.mjs --check     # 寸法・透過・容量・台帳のズレ
npm test                                    # vncheck（整合性）+ smoke（jsdom 実走）
npm run serve                               # → http://localhost:8000/ で見た目を確認
```

手作業でやる場合の注意:

1. **ファイルと `placeholder: false` は必ずセット**。ファイルだけ置くと補完SVGのまま、フラグだけ倒すと 404 で画像が壊れます。
2. **`sw.js` の `CACHE`（現在 `honshitsu-v6`）を上げる**のを忘れると、Service Worker が古いキャッシュを返し続けます。
3. アプリ内のギャラリー「立ち絵」「名場面 CG」タブ（chr-lab / cg-cell）で一覧確認できます。

### 7-3. 名前そのものが演出・解決に影響する箇所（改名するときの注意）

| 箇所 | 何を見ているか | 改名時の影響 |
|---|---|---|
| `js/visual.js` `AssetDB.chrIndex` | 正規表現 `^chr_(.+?)_(\d+)_` | **`chr_<slug>_<2桁番号>_` の形を崩すと解決不能**。語尾（表情名）だけ変えるのは安全 |
| `js/game.js` `guessTime()` | 背景名の語幹（`asa` `yuugata` `yoru` `kaisou` `butsudan` `hokank` `shoko` `sotsugyou` `haru` `namiki` `suunengo`） | **背景名を変えると照明トーンが変わることがある**。`@bg xxx time=akari` を明示すれば名前に依存しない |
| `js/visual.js` `backdropSVG()` | 台帳の `meta`（`kyoshitsu` `yama` `camp` `hawaii` 等） | 補完SVGの絵柄は `meta` で決まる（ファイル名ではない）。`meta` を変えるときは `backdropSVG` の `case` も |
| `js/store.js` `metaUnlock('cg', id)` | **CG の id** | CG の回収記録は localStorage に id で残る → 改名したら `ID_RENAME` に旧→新を足す（版B は `game/js/engine.js` の `CG_RENAME`） |
| 立ち絵の回収記録 | `meta.chr[slug] = [表情番号]` | slug と番号を変えなければ**改名してもセーブは無傷** |

2026-09-13 に実施した命名修正 21 件（読み誤り・混成語）の旧→新対応表は
**`docs/ASSET_MANIFEST.md`「2026-09-13 命名修正」**にあります。原典 `scenareo.txt` は旧表記のまま（履歴として保持）。
